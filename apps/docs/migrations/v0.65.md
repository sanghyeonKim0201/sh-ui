# v0.64.x → v0.65 마이그레이션 가이드

v0.65 의 핵심 변화는 **monorepo 변종에서 컴포넌트 단일 SoT (`packages/ui/ui-core`)**.
v0.64.x 까지는 컴포넌트가 `packages/ui/ui-apps/ui-{app}/src/components/` 마다 복제됐는데,
v0.65 부터 `ui-core` 한 곳에만 emit 되고 ui-app 은 토큰/스타일 전용 (`role: "tokens-only"`).

> standalone 변종 (Next.js single-app) 은 영향 없음 — 이 가이드는 monorepo 변종 한정.

## 자동 도구 — 권장 경로

```bash
# 1. 변경 미리보기 (dry-run, 기본)
npx sh-ui-cli@latest migrate-v065

# 2. 실제 적용
npx sh-ui-cli@latest migrate-v065 --apply

# 3. 적용 후
pnpm install
```

또는 IDE-내 AI 사용 시 `sh_ui_migrate_to_v065` MCP 툴 호출 (`dryRun: true` 기본).

### 자동 도구가 하는 일

1. **컴포넌트 통합** — 모든 `ui-{app}/src/components/`, `src/hooks/`, `src/lib/` 파일을
   `packages/ui/ui-core/` 의 동일한 logical path 로 이동. 같은 path 의 파일이 N 개 ui-app 에
   동일 내용으로 존재하면 dedup, 다르면 abort (자동 병합 안 함).
2. **`ui-core` 부트스트랩** — `sh-ui.config.json` 신규 생성, `package.json` 의 exports 에
   `./components/*`, `./hooks/*` 추가.
3. **`ui-app` 정리** — `sh-ui.config.json` 에 `role: "tokens-only"` 추가, components/utils
   paths/aliases 제거. `package.json` exports 에서 components/hooks/lib 제거.
4. **`apps/*` import 재작성** — `@workspace/ui-{app}/components/...` 패턴을
   `@workspace/ui-core/components/...` 로 일괄 치환 (`.ts`, `.tsx`, `.mjs`, `.js`, `.jsx`).
5. **빈 디렉토리 정리** — 컴포넌트가 모두 옮겨진 ui-app 의 `src/components/`, `src/hooks/`,
   `src/lib/` 디렉토리 자체 제거.

### 안전 장치

- **dryRun 기본** — 실제 변경은 `--apply` (CLI) 또는 `dryRun: false` (MCP) 명시 시에만.
- **충돌 시 abort** — 같은 logical path 의 파일이 ui-app 마다 다른 내용이면 (사용자가
  손본 컴포넌트 가능성) 즉시 abort + 충돌 파일/앱 목록 반환. 자동 병합 시도 안 함.
- **import 재작성 정확성** — `@workspace/ui-{name}/(components|hooks|lib)/` 정확한 패턴만
  치환. 'web' 같은 일반 단어 false-positive 차단.

## 충돌이 났을 때

자동 도구가 abort 하고 충돌 목록을 출력하면, 보통 다음 중 하나:

- **사용자가 한 ui-app 의 컴포넌트를 직접 수정** — 어느 버전을 ui-core 의 단일 SoT 로
  남길지 결정. 다른 앱들의 변종은 별도 컴포넌트로 분리하거나 props 로 분기.
- **다른 시점에 `sh-ui add` 한 컴포넌트가 있어 버전 차이** — 모두 같은 sh-ui 버전으로
  재설치하거나, 가장 최신을 SoT 로 채택.

해결 후 다시 `migrate-v065 --apply`.

## 수동 마이그레이션 (자동 도구 안 쓰고 싶을 때)

자동 도구 없이도 다음 6 단계로 같은 결과:

1. `packages/ui/ui-core/sh-ui.config.json` 생성:
   ```json
   {
     "platform": "react",
     "cssFramework": "plain",
     "paths": {
       "components": "src/components",
       "hooks": "src/hooks",
       "utils": "src/lib/utils.ts"
     },
     "aliases": {
       "components": "@workspace/ui-core/components",
       "hooks": "@workspace/ui-core/hooks",
       "utils": "@workspace/ui-core/lib/utils",
       "ui": "@workspace/ui-core/components"
     }
   }
   ```

2. `packages/ui/ui-core/package.json` 의 `exports` 에 추가:
   ```json
   {
     "exports": {
       "./components/*": "./src/components/*.tsx",
       "./hooks/*": "./src/hooks/*.ts",
       "./lib/*": "./src/lib/*.ts"
     }
   }
   ```

3. 모든 `packages/ui/ui-apps/ui-{app}/src/{components,hooks,lib}/` 파일을 같은 상대 경로로
   `packages/ui/ui-core/src/...` 로 이동 (중복 컨텐츠는 dedup).

4. 각 `packages/ui/ui-apps/ui-{app}/sh-ui.config.json` 갱신:
   - `"role": "tokens-only"` 추가
   - `paths.components`, `paths.utils` 제거
   - `aliases.components`, `aliases.utils`, `aliases.ui` 제거
   - `paths.tokens`, `paths.styles` 는 유지

5. 각 `packages/ui/ui-apps/ui-{app}/package.json` 의 `exports` 에서 `./components/*`,
   `./hooks/*`, `./lib/*` 제거. `./globals.css`, `./postcss.config` 는 유지.

6. `apps/*` 의 모든 `@workspace/ui-{app}/(components|hooks|lib)/` 임포트를
   `@workspace/ui-core/(components|hooks|lib)/` 로 변경.

마지막으로 `pnpm install`.

## 호환성 — 마이그레이션 안 해도 동작?

v0.65 의 `sh-ui add` 는 ui-core 부재 시 자동으로 v0.64.x 레이아웃 (ui-apps 직접 라우팅) 으로
폴백한다. 따라서 마이그레이션을 미루고 v0.65 를 계속 써도 functional regression 은 없다.
다만 컴포넌트 중복 emit 은 그대로 — v0.65 의 SoT 통합 이득은 마이그레이션 후에만.

## 후속 개선

- **v0.66**: `sh_ui_add_app` MCP 툴 추가 — 모노레포에 새 앱 추가가 한 호출. v0.65 layout 자동 준수
  (새 ui-app 도 `role: "tokens-only"`).
- **v0.67**: `sh-ui add <name>` 가 monorepo 어디서든 동작. `apps/web/`, monorepo 루트,
  `packages/ui/ui-core/`, `packages/ui/ui-apps/ui-{name}/` 어느 디렉토리에서 실행해도 walk-up
  으로 자동 라우팅 (tokens → ui-app, 그 외 → ui-core). `apps/web/`에서 `sh-ui add tokens`
  → ui-web 으로 자동 (hintApp 추론).
- **v0.67.1**: `sh-ui add tokens` 가 `rose`/`emerald`/`violet` 등 풍부한 preset 에서 throw 하던
  회귀 수정. 이제 'custom' 과 동일하게 보존 — create 시점의 tokens.css 가 단일 진실.
